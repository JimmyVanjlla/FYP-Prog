# AI-Based Restaurant Resource Management and Order Demand Prediction System

Implementation of Ng Jim Shen's Final Year Project (see `../` for the FYP1
report: Chapters 1-4). Built module-by-module following the sprint order in
Form 2's project schedule. Current status: **Sprint 1 — Module 1 (User &
Access Management) and Module 2 (Menu & Recipe Management)**.

## Stack

- **Backend**: FastAPI + SQLAlchemy + Alembic, Python 3.11, JWT auth, Postgres (Supabase)
- **Frontend**: Flutter (Dart), targeting Android/iOS
- **Background jobs** (from Sprint 2 onward): Celery + Redis, Facebook Prophet, ReportLab

## Backend setup

```bash
cd backend
py -m venv .venv
./.venv/Scripts/pip install -r requirements.txt   # Windows
# source .venv/bin/activate && pip install -r requirements.txt   # macOS/Linux

cp .env.example .env
# Fill in DATABASE_URL (Supabase Postgres connection string) and JWT_SECRET.
# See the comments in .env.example for exactly where to find each value.

./.venv/Scripts/python -m alembic upgrade head
./.venv/Scripts/python -m uvicorn app.main:app --reload
```

API docs (auto-generated by FastAPI): http://127.0.0.1:8000/docs

Run tests:

```bash
./.venv/Scripts/python -m pytest
```

## Frontend setup

```bash
cd frontend
flutter pub get
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:8000
```

`API_BASE_URL` defaults to `http://10.0.2.2:8000` (the Android emulator's
alias for the host machine), which is right for the Android emulator but
wrong for a physical device, iOS simulator, or `flutter run -d chrome` —
override it explicitly for those.

Run tests: `flutter test`. Run static analysis: `flutter analyze`.

## What's implemented so far (Sprint 1)

- **Module 1**: registration, login (JWT), role-based access control,
  Manager staff management (activate/deactivate/reassign role), audit log.
- **Module 2**: menu item CRUD (Manager-only), recipe-to-ingredient links,
  validation on price/quantity. Profit margin calculation and stock-based
  availability are stubbed — both depend on Module 3 (Inventory
  Management), which lands in Sprint 2.

See `backend/app/` (routers → services → models, one file per module) and
`frontend/lib/features/` for the code, and each file's module-level
docstring/comment for which FR(s) it implements.
